# Prom Loader

Прайс-агрегатор и веб-интерфейс для надёжной выгрузки товаров на Prom.ua через [публичное API](https://public-api.docs.prom.ua/):
прайсы поставщиков (XML/YML, Excel, CSV, Google Таблицы) → наценка → карточки товаров → Prom.

Главная идея: **товар сначала сохраняется у вас, а на Prom уходит отдельным шагом**. Если Prom или интернет «упали», ничего не пропадает: товар остаётся в списке со статусом «Ошибка», его можно отправить повторно, а временные сбои очередь повторяет сама.

## Что умеет

**Поставщики (прайс-агрегатор)**
- источник: ссылка на XML/YML, Excel, CSV или Google Таблицу, либо загруженный файл;
- нестандартные прайсы подгоняются вручную: для каждой колонки выбирается, что в ней лежит; любой XML разворачивается в такую же таблицу (атрибуты — колонки `@id`, повторяющиеся теги склеиваются, `<param name="…">` — характеристики, категории YML подставляются названием);
- настройки колонок сохраняются, дальше обновление идёт по расписанию (каждый час … раз в сутки) или по кнопке;
- новые позиции создают товары (черновиками или сразу «готов к отправке»), у существующих обновляются цена, наличие и прочие данные;
- **ваши ручные правки не затираются**: изменённое в карточке поле помечается «🔒 своё», поставщик его больше не трогает; значение поставщика можно вернуть одним нажатием;
- пропавшие из прайса товары получают «нет в наличии», вернувшиеся снова появляются в продаже;
- **защита от битого прайса**: если товаров в прайсе стало меньше половины от прошлого раза, обновление останавливается и ничего не меняет (можно запустить принудительно);
- префикс артикула, если артикулы разных поставщиков пересекаются; уже существующий товар с тем же артикулом привязывается к поставщику;
- при желании изменения сразу уходят на Prom;
- история обновлений с числом новых, изменённых, пропавших товаров и примерами строк с ошибками.

**Наценка**
- правила по поставщику, группе и диапазону закупочной цены: `закупка × (1 + %) + грн`;
- округление: до целого, до десятков, «на 9» (1231 → 1239), «на 99»;
- режим «продавать по РРЦ», если поставщик её даёт;
- правила проверяются сверху вниз, есть калькулятор для проверки и кнопка «пересчитать все цены»;
- цена никогда не опускается ниже закупочной; цена, изменённая вручную, не пересчитывается.

**Карточка товара**
- автосохранение при каждом изменении; при обрыве связи правки хранятся в браузере и досылаются, когда сервер снова доступен (даже если закрыть вкладку);
- фото: перетаскивание в любое место окна, вставка из буфера (Ctrl+V), выбор файлов, добавление по ссылке; порядок меняется перетаскиванием, первое фото — главное; если одно фото не загрузилось, у него есть кнопка «Повторить»;
- живое превью «как на Prom»: страница товара и плитка в каталоге, на русском и украинском;
- проверка перед отправкой: что мешает выгрузке (ошибки) и что стоит дополнить (предупреждения);
- характеристики, скидка (старая цена), наличие и количество, группа, производитель, ключевые слова, дублирование товара.

**Разовый импорт из файла (Excel, CSV, XML/YML)**
- выбор листа и строки с заголовками;
- выбор строк галочками (Shift+клик — диапазон) или текстом: `2-50, 55, 60-`;
- над каждой колонкой указывается, что в ней лежит: название, цена, артикул, фото и т.д.; сопоставление по заголовкам подбирается автоматически; любую колонку можно сделать характеристикой;
- фото берутся из колонки со ссылками **и из картинок, вставленных прямо в ячейки Excel**;
- перед импортом карточки показываются в виде плиток с ошибками по каждой строке;
- при повторном импорте товары с тем же артикулом обновляются, а не дублируются.

**Список товаров**
- фильтр по статусу и поставщику, поиск, подгрузка страницами (рассчитано на десятки тысяч товаров);
- массовые действия (отправить, пометить «готов», в черновики, удалить);
- быстрое создание: перетащите пачку фото, и на каждое создастся черновик;
- панель очереди отправки с результатами импорта Prom и кнопкой «Повторить».

**Выгрузка на Prom**
- выбранные товары собираются в YML-файл и отправляются через `POST /products/import_file`; статус проверяется через `GET /products/import/status/{id}`;
- очередь хранится в базе и переживает перезапуск сервера;
- сетевые ошибки, 429 и 5xx повторяются с нарастающей паузой (10 с → 15 мин, 8 попыток); неверный токен и ошибки данных сразу показываются у товара;
- если товар отредактировали во время отправки, он не будет ошибочно помечен «На Prom»: он снова встанет в очередь;
- постоянная ссылка на YML-фид (`/feed/prom.yml?key=…`) для автоимпорта по расписанию в кабинете Prom.

## Запуск

Нужен Python 3.10+.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn promloader.main:app --host 0.0.0.0 --port 8000
```

Откройте http://localhost:8000, затем в разделе «Настройки» укажите API-токен и публичный адрес сайта.

Данные (база SQLite и фото) хранятся в папке `data/`. Её и нужно бэкапить.

### Переменные окружения (необязательно)

| Переменная | Назначение |
|---|---|
| `PROMLOADER_DATA` | папка с данными (по умолчанию `data`) |
| `PROM_API_TOKEN` | токен Prom (иначе задаётся в «Настройках») |
| `PUBLIC_BASE_URL` | публичный адрес сайта, например `https://loader.example.com` |
| `APP_PASSWORD`, `APP_USER` | закрыть интерфейс паролем (логин по умолчанию `admin`); фото и фид остаются открытыми, их забирает Prom |
| `PROM_API_BASE` | адрес API (по умолчанию `https://my.prom.ua/api/v1`) |

### Почему нужен публичный адрес

Prom не принимает фото файлами: он скачивает их по ссылкам из YML. Поэтому загруженные сюда фото должны быть доступны из интернета. Подходящие варианты:
- VPS с доменом (обязательно с `APP_PASSWORD`);
- туннель с домашнего компьютера (Cloudflare Tunnel, ngrok).

Фото, добавленные по внешним ссылкам, работают и без этого.

## Что сверить с документацией Prom

Методы `import_file`, `import_url`, `import/status/{id}` и `edit_by_external_id` есть в документации Prom. Точные имена полей запросов и ответов собраны в одном файле, `promloader/prom_api.py`:
- настройки импорта (`mark_missing_product_as: "none"` и др.) можно поменять без правки кода: «Настройки → Дополнительно»;
- значения статуса импорта (`SUCCESS` / `PARTIAL` / `FATAL`…) заданы в `IMPORT_DONE_OK` и `IMPORT_DONE_FAIL`;
- теги YML (`available`, `oldprice`, `quantity_in_stock`, `param`…) собраны в `promloader/feed.py`.

Перед работой на реальном магазине стоит прогнать выгрузку на тестовой компании Prom (песочнице), как рекомендует документация API.

## Производительность

Прайс поставщика на 50 000 товаров (YML ~20 МБ) обрабатывается примерно за 10 секунд, повторное обновление — столько же.
Обработка идёт пачками по 500 товаров, интерфейс во время обновления не блокируется.

## Структура

```
promloader/
  main.py       веб-сервер и API
  products.py   товары, проверки, фото, закреплённые поля
  suppliers.py  поставщики: загрузка прайса, обновление, пропавшие товары, защита от битого прайса
  pricing.py    правила наценки и округления
  excel.py      разбор Excel/CSV/XML, выбор строк, сопоставление колонок
  feed.py       генерация YML для Prom
  prom_api.py   клиент API Prom.ua
  sync.py       очередь отправки с повторами
  db.py         SQLite
  static/       интерфейс (без сборки: HTML + JS)
tests/
```
